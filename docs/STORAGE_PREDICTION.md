# Storage-only predictors

`storage_prediction/1` is an optional compression role in capsule2. It grants no engineering response, field availability, case certification or new-case evaluation. Mixed native-affinity exports may retain qualified primitive columns with literal zeros at native rows solely to predict stored words. VM/EQ predictors derive from primitive predictions using existing runtime rules; principal predictors are omitted. Dynamic/selected layouts remain on the explicit route.

ANYpost stores `xor_storage_prediction_sha256/1`: every original float64 word is XOR-corrected and SHA256-protected per persisted case/spatial chunk, at most256KiB. A partial read validates the complete integrity tile before returning selected values. Verified tiles consume the configured cache budget; dependencies, conversion, output and tile scratch consume the configured working budget, capped at128MiB. Missing stored rows never use the predictor as a scientific fallback.

Finite-input prediction overflow may write a durable zero-prediction tile. Readers follow the recorded branch and verify decoded SHA256; a changed platform/runtime prediction or corruption is a typed refusal. This is integrity detection, not a universal cross-platform binary64 portability guarantee. A supplied predictor has no physical meaning at padded native rows.

New decoding requires `ANYpost[results]` with anysolver-results2.1 capability `STORAGE_PREDICTION_API=1`. Metadata discovery and old plain/numeric-XOR reads remain runtime-free. Capsule/runtime2 and ordered_float64/1 scientific semantics are unchanged. The lightweight validator imports only NumPy and validates structure; it does not certify arbitrary metadata or element physics.

An unused staged storage role can be withdrawn only with zero target rows and zero new-codec datasets. Existing failed input handling remains fail-fast, preserves the previous destination and publishes terminal diagnostic evidence. No empty successful recovery records or fabricated field descriptors are introduced.


Reader/writer implementation uses adaptive persisted integrity chunks, at most256KiB of decoded words, sized from pattern width and the complete simultaneous primitive closure. Normal writer tiles target64MiB active predictor scratch to leave output/index headroom under the128MiB ceiling; a one-row fixed cost above128MiB is refused. Readers still validate the whole persisted tile and may honestly refuse an older wide tile under configured limits. Writer dependency bases are loaded once per tile/write event, outside its case loop. Reader bases share the ordinary byte-accounted LRU across cases; decoded source SHA verification remains per case/tile. Active references count toward working space even when evicted or already cached. Cache0 retains no basis and preserves correctness.

Custom predictor namespace names make no independently certified physical assertion. A custom byte prediction may be inaccurate; XOR corrections plus decoded-word SHA retain actual stored values. Engineering VM/EQ/principal definitions and the solver producer remain governed separately: solver-produced VM/EQ predictions derive from primitive columns and principal values remain plain. Custom storage roles cannot grant field availability, recover missing rows or admit new combinations.

Archive writers share identical canonical int64 association tables within one model-revision transaction through HDF5 dataset hardlinks. Every component and storage-role logical path remains present with the original shape, dtype, chunks and filters; responses and component groups are never aliased. Content hashing and collision checks use bounded blocks, and the pool retains no numeric copies. Storage-role association SHA validation remains mandatory even when both paths name the same physical object. Geometry identity arrays retain their separate node/element semantics.


`write_results` and `ArchiveSink` accept either `cancel_event=None` (an `is_set()` object, raising public `RequestCancelled`) or `cancel_check=None` (a callable that raises its owner's cancellation exception unchanged). Supplying both is rejected before file mutation. For source export, pass `CancellationToken.raise_if_cancelled` as `cancel_check`; the source exporter itself takes `CancellationToken`, not an Event. New predictor encoding checks at dependency/row boundaries and normal publication checks again before replacing the destination. Stream cancellation aborts and preserves existing terminal diagnostics; direct writes remove their partial temporary file and preserve the previous destination. Defaults retain the previous successful transaction semantics.

The writer observes `peak_encode_work_bytes` as a transport HDF attribute; stream diagnostics expose the same peak. This is not engineering metadata or a configurable writer cap. Predictor tiles remain bounded by the existing128MiB implementation ceiling. Reader reservations now include the complete simultaneous tile closure, outer output/selection reservation and a conservative64bytes per selected/scatter entry; cached tiles remain active byte references. Primitive temporary references are released after verified decoding. The ordered predictor uses row-sized output, scratch and NaN masks, not an extra row×pattern matrix.

Owner cancellation callbacks may raise BaseException stops such as KeyboardInterrupt or SystemExit. Stream event/final-publication failures durably abort even without a context manager; a one-shot observed stop cannot later be retried into publication. Context exit performs abort cleanup in finally, and the aborted state is latched before file cleanup.
